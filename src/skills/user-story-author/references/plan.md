# Plan independent Stories

Apply the [shared contract](story-contract.md). Read the stated need and only
context necessary to locate value, outcomes, constraints and dependencies.
Propose independently meaningful slices with a beneficiary/outcome, scope in/out,
acceptance direction, dependencies, delivery boundary and reason for each cut.
Explain sequencing when a slice depends on another; mark proposed local labels
as local, not provider IDs. Keep open decisions and authority with their owners.

Split by independent observable value/outcome, risk or delivery boundary, not by
verbs, layers or a predetermined number of items. An implementation step with no
independent outcome may be a Task within its existing Story. A technical Story is
appropriate when it has its own useful outcome, bounded scope and acceptance.
Do not generate empty Epic/Feature/Story/Task shells or one Issue per activity.
Do not promise independent delivery when dependencies prevent it.

Research may be a bounded learning Story. State the learning question, intended
evidence output, supplied time/scope bound (unknown if absent), stopping criterion
and decision owner. A proposed stopping criterion must be labelled proposed.
Do not claim a production capability or successful experiment before evidence.
Adapt the technical template if a full research Story is requested.

Return proposed slices and reasons, unresolved decisions and the smallest next
step under current authority. Planning alone does not create work items or authorize
implementation. Load a Description template only if asked to draft the slices.
