# Review a whole Story or selected AC

Apply the [shared contract](story-contract.md). Bind the subject and its version or
supplied text before review. State whether the selection is the whole Story or
exact AC IDs/content spans. If selection is ambiguous, resolve it before claims
about that selection. Do not require reviewing a whole Story first.

Read only context needed to interpret the selected subject: value, applicable
rules, dependencies, accepted decisions and relevant neighbouring AC. Cross-AC
context can establish a finding about a selected AC; it does not expand the report
scope. Report findings only in the selected subject. Never rewrite the subject,
unselected AC, provider fields or work-item state. Export only when requested.

Assess meaning, source traceability, scope consistency, observable acceptance,
failure/exception boundaries and ambiguity relevant to the selection. Distinguish
a proven defect from missing input or uncertainty. Each finding includes selected
location, source/evidence, defect or uncertainty, consequence and bounded suggestion.
Use no arbitrary finding count. Do not report hypothetical failures as established.
A source conflict needs its actual owner; reviewer preference is not a requirement.

Keep test-case design, test levels, test data, oracle machinery and coverage with
test-designer. If requested separately, hand off accepted criteria, source identity,
unknowns and current authority without inventing a mandatory pipeline.

Return subject/scope, findings (or no findings within that scope), consulted context
and material limits/open decisions. No findings is a bounded review result, not
product acceptance, approval, test execution or proof of all unexamined content.
