# User-value Description template

Use the [shared contract](../story-contract.md) and separate Title/AC fields.
These are Description headings, not mandatory provider fields.

## User Story
State the actor, desired capability and value using supplied intent.

## Background
Describe supplied As-Is and Why; identify missing evidence without invented pain.

## User Scenarios
Describe relevant role, timing, entry, goal and exceptions. Do not turn these into
a mandatory formal test matrix.

## Functional Requirements
Capture supplied behavior and source FR IDs (or explicitly proposed local labels).
Include input/output/UI only when relevant and supported.

## Scope
State in-scope and excluded outcomes; keep undecided boundaries visible.

## Open Questions
List unresolved decisions and impact; omit this heading if empty.
