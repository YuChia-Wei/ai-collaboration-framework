# External AI Discussion And Evidence Intake

External discussion provides attributed advice, not repository authority or
permission to write. Give the external reviewer one bounded question and a
reproducible input; preserve the original response when bringing it back.

## Discussion Brief

Record topic, repository, full source commit or input digest, included files,
exclusions, existing invariants, decision questions and desired feedback. State
that the discussion is advisory. Provide the relevant files explicitly; do not
rely on hidden conversation history or assumed repository access.

For long discussions, retain intermediate syntheses with agreed points,
disagreements, missing evidence and the next question. Ask for a portable final
result identifying its subject, assumptions, options, tradeoffs, unresolved
questions and evidence or commands needed to reproduce material claims.

## Return To The Project

Retain the brief, original response, reviewer attribution and date in a
project-selected destination when persistence is requested. Verify the input
identity and reproduce material claims using direct project evidence. Separate
confirmed, added, downgraded, overturned and unresolved claims. Keep stable
finding IDs where the project uses them.

The project owns assessment formats and remediation authorization. Advice may
finish in the conversation; persistence does not force a workflow. Only findings
selected under actual owner authority proceed to edits, backlog creation or
other provider operations. Do not promote a summary to canonical rules or erase
original dissent in order to match a template.

Discuss large rule sets by topic: classify normative rules, examples and
explanations; verify duplication and conflicts; compare placement alternatives;
then review compatibility and validation consequences. Total file size is not
measured token cost, and a proposed validator is not evidence of execution.
