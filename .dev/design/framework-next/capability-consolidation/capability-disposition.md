# Capability disposition proposal

Status: proposal, not availability or adoption. The [16 exact records](legacy-skills.json) preserve canonical skill.yaml, declared outputs/references, owned tracked paths and source-line dependency evidence. The inventory covers explicit source references, not recursive loading of old workflows or all technology assets.

Keep specialist reasoning in package-contained instructions. Make project requirements, adopted architecture, selected tests and destinations explicit inputs. Missing selected specialist coverage is visible, not a clean result. Retain useful shared meaning under one selected owner; do not install the legacy governance tree just to satisfy links. A source human guide can inform extraction but cannot remain a package dependency.

Instruction operations may inspect or author authorized target files without claiming deterministic results. Plain prose uses ordinary templates/instructions and caller destinations: no compulsory JSON schema, store or artifact role. Persistent machine-owned formats require an accountable schema/lifecycle owner, real reader/validator and useful bounded writer. Optional collaboration returns a candidate when absent; it must not disable the primary capability.

## Shared and technology ownership

The first reasoning package can contain minimal common review instructions in references/review.md without importing source-only shared contracts. Introduce reusable product assets only when implemented consumers need the same public contract and the coordinator selects one owner. No generic registry, plugin loader or mandatory shared package is proposed.

Technology path occurrences include inactive roles and patterns; they are not proof that all must ship. Future authors select concrete package-contained resources. Unselected dotnet never activates automatically. The direct dependency evidence remains reproducible; patterns and unresolved paths are retained instead of guessed.

An absent maintenance/install skill cannot block ordinary review/ADR. An optional maintenance skill cannot publish, restore CI, change credentials or overwrite target truth merely by being installed. Root legacy routes remain active until coordinator cutover.
