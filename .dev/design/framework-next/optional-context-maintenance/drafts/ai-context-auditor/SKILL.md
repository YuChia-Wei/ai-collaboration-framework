# AI Context Auditor

Design specimen for #352, not installed/registered. At implementation, the entry
keeps the purpose/operations and routes to package-local references/audit.md;
the method below becomes that reference. No design/source-policy link is shipped.

## Entry and operations

Use audit for a scoped question and compare for selected before/after evidence.
Obtain context scope, relevant authority, intended behavior, subject evidence and
optional presentation/export. Return findings/limits without modifying audited
context. This optional instruction package has no config, store, executable,
schema or skill dependency. It needs an instruction reader and permitted evidence.

## Audit method draft

1. Select named files/roots/rules and exclusions. Default exclusions are product
   source/tests, dependencies, generated build output, secrets and unrelated
   history. Product-code review is a separate capability, not scope expansion.
2. Identify subject and active ownership/instructions. Separate adopted project
   rules, package baseline, customizations, source-only policy, history and
   suggestions. Missing semantic authority is unresolved.
3. Examine the actual selected content for contradictions, ambiguous ownership,
   broken/stale references, duplicate normative statements, unsupported execution
   claims or drift from a supplied baseline. Consider whether the project rule
   itself explains intended behavior; self-declared compliance is not evidence.
4. Verify material claims against direct sources. Optional indexes may help when
   freshness/coverage is known; missing results are not proof of absence. Use a
   bounded direct fallback and report remaining gaps; no required index install.
5. Return finding location, concrete trigger/impact, evidence, confidence and
   alternatives, plus scope and actual/not-run checks. No supported findings in
   scope is not a global health certificate.

## Compare method draft

Read both selected subjects and prior findings. Preserve their existing identities
and conclusions. Recheck claims against current evidence and map requested findings
to confirmed, changed, resolved by observed evidence, or unresolved. Report new
issues and exclusions. Missing before evidence is unresolved; do not reconstruct
a baseline. A changed file alone proves no resolution. A same-agent comparison
is not an independent audit. Review requirements remain with actual project/task
authority. No automatic finalization, workflow closure or adoption.

## Output and persistence draft

Use caller formatting or prose: subject/scope, findings/evidence, uncertainties,
observed checks and next actions. No destination means chat. Explicit export uses
a selected project-owned destination outside audited bytes, after current-content/
ownership/containment checks; never overwrite final conclusions. Project templates
must preserve source/status/identity distinctions. Selected structured records use
their existing owner's supported public operation; unknown versions stay intact.
No global identity allocator, store or index.

Governance absence leaves an actionable proposal; do not install it implicitly.
A remediation request hands off the concrete selected change under actual
authority while this auditor remains read-only toward its subject.
