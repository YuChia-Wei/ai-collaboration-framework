# Project Knowledge And Governance

`.dev` contains records, rules and collaboration directly related to developing
this framework: decisions, requirements, assessments, workflows, source policies,
project-specific guides and evidence-backed lessons. Humans and agents share
this project truth. Use [INDEX.md](INDEX.md) for navigation.

Editable reusable capabilities belong in `src`; human product manuals belong in
`docs`; `.ai/core` and runtime entries are managed installation outputs. This
repository both develops and consumes the framework, so source and installed
copies may coexist. Prepare reusable content in source before a separately
selected self-installation. Do not treat copying or installation as adoption of
project rules or execution of initialized project records.

Existing design, assessment, requirement, ADR and workflow history is excluded
from the 2026-10-03 cleanup. Useful lessons and actual release/support duties keep
their owners. Obsolete instructions without independent experience-transfer
value can be removed; historical references remain retrievable through Git.

Release identity stays in `releases`; live Issues own current work authority;
workflow records retain execution state. These states are distinct from
integration, publication and downstream adoption.
