## user_value

### Title
會員關閉電子郵件通知後可確認儲存結果

### Description

#### User Story
身為會員，我希望關閉電子郵件通知並儲存，讓電子郵件通知偏好反映我的選擇，且能辨識此次儲存是否成功。（R-U v1）

#### Background
R-U v1 已接受：成功時 EmailEnabled=false 並顯示「已儲存」；失敗時顯示「未儲存」且兩個偏好維持原值。既有畫面與儲存機制的現況未提供，無法推定目前缺陷或使用痛點。

#### User Scenarios
會員在偏好設定情境關閉電子郵件通知並儲存。成功時看到「已儲存」，EmailEnabled 為 false，PhoneEnabled 保持儲存前值。儲存失敗時看到「未儲存」，EmailEnabled 與 PhoneEnabled 都保持儲存前值。實際畫面入口未提供。

#### Functional Requirements
依 R-U v1，關閉電子郵件通知並儲存成功後，EmailEnabled=false，畫面顯示「已儲存」，既有 PhoneEnabled 不變。儲存失敗時顯示「未儲存」，兩個偏好均保持原值。

#### Scope
包含關閉電子郵件通知的儲存成功與失敗結果，以及 PhoneEnabled 的保留。其他偏好功能及通知發送行為不在本份來源支持的範圍。

#### Open Questions
實際畫面入口、既有儲存流程及如何辨識儲存失敗尚未提供；接手實作前需定位，不能由草稿推定技術方式。

### Acceptance Criteria

- [ ] 會員關閉電子郵件通知並儲存成功後，EmailEnabled=false，畫面顯示「已儲存」。
- [ ] 上述儲存成功後，PhoneEnabled 與儲存前值相同。
- [ ] 關閉電子郵件通知的儲存失敗後，畫面顯示「未儲存」，EmailEnabled 與 PhoneEnabled 均與儲存前值相同。

### 交接脈絡
來源：R-U v1，已接受；本文件為文件草稿，AC 尚未執行或驗收。沿用決定：成功／失敗訊息、EmailEnabled 成功值及兩偏好保留規則。無真實父項／工作項 ID；沒有已知跨項依賴，實際程式關聯尚未建立。第一步：依本草稿確認既有會員偏好入口與儲存邊界，再由需求 owner 處理未決資訊。目前只授權文件草稿；provider 寫入與實作需另行授權。

## business_rule

### Title
資料匯出工作建立限 Owner，Editor 請求被拒絕

### Description

#### Objective
讓資料匯出建立權限符合 R-B v2，保障資料匯出流程遵守只有 Owner 可建立工作的規則。受影響角色為 Owner 與 Editor；具體業務受益者及規則原因未提供。

#### Background
R-B v2 已接受；既有權限行為與問題現況未提供。Owner 請求的其餘有效性規則尚未提供。

#### Expected Behavior
要求建立資料匯出工作時適用此權限規則。Editor 要求時拒絕，且不建立匯出工作。Owner 是唯一可建立工作的角色；其餘有效性條件未知，因此不能推定每個 Owner 請求都應建立成功。

#### Business Rules
R-B v2：只有 Owner 可建立匯出工作；Editor 要求時必須拒絕且不建立工作。沒有來源支持的例外、優先序或生效日期；其他角色的具體拒絕呈現方式未提供。

#### Scope
包含建立資料匯出工作的角色限制及 Editor 拒絕結果。不延伸至匯出內容、下載權限或排程方案；完整 Owner 成功流程待其餘有效性規則補充。

#### Open Questions
請需求 owner 補充 Owner 請求有效性規則與成功建立條件，影響完整正向路徑的驗收。其他角色及拒絕呈現方式未提供，不推造訊息或狀態碼。

### Acceptance Criteria

- [ ] Editor 要求建立資料匯出工作時，要求被拒絕，且沒有因該要求建立匯出工作。
- [ ] 任何已建立的資料匯出工作，其建立請求角色必須是 Owner；此條件不代表所有 Owner 請求都有效或都建立成功。

### 交接脈絡
來源：R-B v2，已接受；本文件為草稿，AC 未執行或驗收。已接受權限規則如上，Owner 其他有效性規則仍未知；完整 Owner 正向驗收尚無足夠來源。無真實父項／工作項 ID，也無已知跨項依賴。第一步：向需求 owner 取得其餘有效性規則，再補足正向條件。目前只授權文件草稿，沒有 provider 寫入或實作授權。

## technical

### Title
CSV exporter 使用 UTF-8 無 BOM 與 LF 並保留資料內容及順序

### Description

#### Technical Objective
使 CSV exporter 達成 R-T v1 指定的輸出格式，並保留既有資料內容與順序。受益對象為 CSV 輸出使用端；具體使用端身分與格式變更原因未提供。

#### Current State and Problem
R-T v1 已接受編碼與換行變更，並明訂須保留原本 [id,title] 欄位順序、每列值及列順序。實際程式位置與目前編碼／換行狀態未提供，不能宣稱目前使用何種格式。

#### Expected Outcome
CSV 輸出採 UTF-8 無 BOM、LF 換行；欄位依序為 id、title，保留原本每列值與列順序。

#### Technical Requirements and Constraints
依 R-T v1，格式必須為 UTF-8 無 BOM、LF；保留 [id,title] 欄位順序、每列值及列順序。未提供技術棧、程式位置、部署方式或具體實作方法，不預設。

#### Scope
包含 CSV exporter 的編碼、換行及上述保留條件。不包含資料匯出建立權限、資料內容變更或排程方案研究。

#### Open Questions
實際 exporter 程式位置與既有輸出依據未知；影響修改定位與保留行為的比對，接手者需先取得。

### Acceptance Criteria

- [ ] CSV exporter 產出的 CSV 採 UTF-8，且不含 BOM。
- [ ] CSV 的換行採 LF。
- [ ] 變更後欄位順序仍為 [id,title]，每列值與列順序均與原本相同。

### 交接脈絡
來源：R-T v1，已接受；本文件為草稿，AC 未執行或驗收。已接受格式與保留約束如上；實際程式位置未知。無真實父項／工作項 ID，沒有已知跨項依賴。第一步：取得 exporter 位置及既有輸出依據，讓接手者能定位變更並比對保留條件。目前僅授權文件草稿，沒有 provider 寫入、實作或測試執行授權。
