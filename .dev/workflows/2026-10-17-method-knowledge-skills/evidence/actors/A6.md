## 1. requirement-author draft：停用帳號需求

文件狀態：草稿；需求行為來源：已接受 R1(v1)。目標是讓 Manager 停用 Account A，並保留非 Manager 請求遭拒時的帳號狀態。

| 條件／角色 | 需求與可觀察結果 | 來源 |
| --- | --- | --- |
| Manager 請求停用 Account A 且成功 | Account A 的 Enabled=false | R1(v1)，已接受 |
| 非 Manager 請求停用 Account A | 請求遭拒，Account A 狀態與請求前相同 | R1(v1)，已接受 |

可觀察驗收條件：

- Manager 對 Account A 提出停用請求並成功後，能觀察 Account A 的 Enabled=false。
- 非 Manager 對 Account A 提出停用請求後，能觀察拒絕結果，且 Account A 狀態保持請求前原值。

此處是 R1 的文字表達，未創造外部 AC ID。角色來源、帳號不存在的結果、重複停用、效能門檻及稽核要求未提供，保留未知；不新增其行為。技術分工見已接受 D1(v2)，不將其擴寫成新的使用者需求。

## 3. spec-author draft production：DisableAccount

類型：production，描述單一停用行為；文件狀態：草稿。來源：R1(v1) 已接受的結果與權限規則；D1(v2) 已接受的責任分工。

- 觸發者：請求停用 Account A 的 actor。
- 行為需要的資訊：actor 角色與目標 Account A。此項不指定程式型別、參數名稱或傳輸格式。
- application 檢查 actor 角色。Manager 路徑通過後呼叫 Account.Disable；成功後 Account A.Enabled=false。
- 非 Manager 路徑遭拒，Account A 狀態不變。拒絕應可觀察；具體結果格式在本項來源中未指定。
- Account 擁有 Enabled 狀態。application 與 Account 在相同 process，兩者之間沒有網路呼叫。

| 規則來源 | 條件 | 後置結果 |
| --- | --- | --- |
| R1(v1)、D1(v2) | Manager，停用成功 | application 已檢查角色並呼叫 Account.Disable；Enabled=false |
| R1(v1)、D1(v2) | 非 Manager | 拒絕且狀態不變 |

驗收期望：觀察 Manager 成功後的 Enabled=false；觀察非 Manager 的拒絕與原狀態保留。這些是合約期望，沒有執行證據。帳號查找、帳號不存在、原先已停用、持久化、交易、併發、重試、取消與事件均未指定；不以草稿填入決策。

| 成員 | 已知合約 | 未知 |
| --- | --- | --- |
| Enabled | 由 Account 擁有；停用成功後為 false | 程式型別、初始值、可見性與其他取值限制未提供 |
| Disable | application 在檢查 actor 角色後呼叫；成功後 Enabled=false | 參數、回傳型別、可見性、重複呼叫與其他無效轉移結果未提供 |

權限檢查責任在 application（D1(v2)）；沒有來源支持將角色政策移入 Account。非 Manager 的整體請求遭拒且狀態不變（R1(v1)）。可觀察的 entity 狀態期望為成功停用後 Enabled=false。

Account 的識別與相等性、關聯、aggregate 歸屬、持久化、序列化、併發及其他生命週期狀態皆未知，保留待決。沒有擴增欄位、事件或 entity 層錯誤政策。

## 5. spec-author draft adapter：既有 in-process 停用入口

類型：adapter，描述既有程序內入口合約；文件狀態：草稿。來源：D2(v1) 已接受的輸入與結果，R1(v1) 已接受的行為，D1(v2) 已接受的分工。

| 入口 | 輸入 | 回傳 | 邊界 |
| --- | --- | --- | --- |
| 既有停用入口，實際程式名稱未提供 | actorRole、accountId | Disabled 或 Forbidden | in-process；不增加 transport |

| 輸入／結果 | 映射與語意 | 來源 |
| --- | --- | --- |
| actorRole | 供 application 檢查角色；不代表角色真實性的驗證方式已決 | D1(v2)、D2(v1) |
| accountId | 指定停用目標；型別、查找方式及不存在時結果未提供 | D2(v1) |
| Disabled | Manager 停用成功，目標 Account.Enabled=false | R1(v1)、D2(v1) |
| Forbidden | 非 Manager 的業務拒絕，目標 Account 狀態不變 | R1(v1)、D2(v1) |

入口將請求交由 application；application 檢查角色後呼叫 Account.Disable（D1(v2)）。沒有網路邊界，因此不定義 HTTP 路由或 status code。呼叫端身分、角色可信來源、輸入驗證、找不到帳號、例外映射、重試、取消與逾時政策未提供，保留未知。驗收期望為輸入／結果映射與狀態結果符合上述來源，未宣稱已實作或執行。
